# Java serverless deployment contract

This page describes the published `feature/serverlessshell` revision recorded in the [research index](README.md). The Java shell is a distinct executable that embeds OpenSearch libraries, Netty, and repository code. Its deployment starts at `org.opensearch.serverless.shell.ServerlessBootstrap`.

## Launch and configuration

| Input | Behavior in the inspected Java revision |
| --- | --- |
| Executable | `ServerlessBootstrap.main` starts the shell and waits for shutdown. The process harness invokes it directly with a production runtime classpath, JVM module opens, and Netty options. |
| Settings | The entry point forwards JVM system properties starting with `serverless.`, `node.`, `cluster.`, `path.`, `http.`, `transport.`, `network.`, `thread_pool.`, and `telemetry.`. It ignores application arguments and has no `opensearch.yml` reader. Unknown serverless setting names are logged and ignored. |
| Local paths | The harness supplies a private `path.home` and config directory per process. `path.conf` selects the shell keystore directory and defaults to `path.home/config`. S3 also needs the JVM system property `opensearch.path.conf`. Use the intended config directory for both. |
| Roles | Unset `serverless.roles` means `ingest,search`. An explicit empty value means coordinator-only. The parser accepts comma-separated `ingest` and `search` and rejects unknown tokens. Search readiness changes the roles advertised in the lease. |
| Plugins | `serverless.plugins` names optional classes already on the runtime classpath. The shell also uses the core plugin loader for plugins installed under its home. The image must supply and test the plugins used by the selected configuration. |

## Object storage and credentials

| Setting | Meaning |
| --- | --- |
| `serverless.store.type` | `fs` by default. The process supports `fs` and `s3` for its primary store. |
| `serverless.store.path` | Required for `fs`. This path is the backing store, distinct from Pod-local shard state. The filesystem backend depends on atomic filesystem and locking semantics. |
| `serverless.store.bucket` | Required for `s3`. The metadata plane starts at the bucket root. Independent deployments need exclusive buckets with this revision. `cluster.name` supplies a label and does not partition the store. |
| `serverless.store.endpoint` | Optional object-store endpoint override. |
| `serverless.store.region` | `us-east-1` by default. |
| `serverless.store.path_style_access` | `false` by default. Set it for a compatible endpoint that requires path-style addressing. |
| `serverless.store.provider_ack` | Suppresses the provider warning. It has no effect on store behavior or conformance. |

[Store settings](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/store/ObjectStoreSettings.java) · [Store factories](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/store/ObjectStores.java) · [Metadata plane construction](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/ServerlessBootstrap.java#L219)

The shell links `repository-s3` at build time and uses its factory to build an internal `serverless` repository from these startup settings. OpenSearch's standard remote-backed storage uses named `node.attr.remote_store.*` repositories. The serverless shell instead opens a single primary object store at process startup. The operator's named repository reference resolves to this startup configuration. [Shell Gradle dependencies](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/build.gradle#L33-L43) · [Factory setup](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/store/ObjectStores.java#L120-L137) · [Standard remote-backed storage](https://docs.opensearch.org/latest/tuning-your-cluster/availability-and-recovery/remote-store/migrating-to-remote/) · [Operator storage API](../design/api-and-resources.md#primary-s3-remote-store)

Static S3 credentials use secure keystore settings such as `s3.client.default.access_key` and `s3.client.default.secret_key`. Bootstrap loads the keystore once at startup. A missing keystore is allowed and a password-protected keystore is rejected. The S3 plugin also contains a web-identity provider path. Workload identity support requires verifying the chosen image, provider, and credential refresh behavior together. [Secure settings loading](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/ServerlessBootstrap.java#L349) · [S3 credential selection](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/plugins/repository-s3/src/main/java/org/opensearch/repositories/s3/S3Service.java)

Use a disposable S3-compatible store for multi-Pod tests. The operator should keep the user-supplied bucket and its credentials outside its deletion lifecycle. Object storage carries durable metadata, shard registers, WAL records, and segments. Local storage still needs capacity for Lucene files, caches, and recovery spooling. The internal node ID is derived from `NodeEnvironment`. Replacing its local data directory can change the node ID. ## Membership and network

Startup binds HTTP and transport, opens the store, attaches the metadata plane, attempts an initial lease renewal, and starts the scheduler. The default lease TTL is 30 seconds. The bootstrap sets the nominal renewal interval to one third of the TTL. The lease carries the node ID, process incarnation, published transport address, and advertised roles. [Bootstrap](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/ServerlessBootstrap.java) · [Node settings](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/node/NodeSettings.java) · [Lease writers](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/node/NodeLeases.java)

A Kubernetes HTTP Service can route client traffic. Native transport uses the individual peer address in the lease, so publish a reachable address for each Pod and verify it from another Pod. A shared load-balanced address cannot identify the peer selected by the router. A classic discovery Service and elected cluster manager have no role in this membership model. [Native router](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/transport/ShardRouter.java) · [Lease membership](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/membership/BlobLeaseMembership.java)

`serverless.transport.require_secure` defaults to false. Its startup check looks at the transport type and available secure settings factories. Qualify the real peer TLS handshake and credentials with the selected image. HTTP authentication is separate. The optional shell Basic auth plugin authenticates callers, and authorization depends on the configured action filters or the deployment boundary. Verify which probe requests the chosen HTTP authentication path permits. Expose the state-changing drain endpoint only through the intended administrative access path. [Transport startup](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/node/NodeStartup.java) · [HTTP handler wrapper](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/NodeWiring.java) · [Shell auth plugin](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/auth/src/main/java/org/opensearch/serverless/auth/ServerlessAuthPlugin.java)

## Startup, readiness, and termination

| Signal | What it establishes |
| --- | --- |
| `serverless.ready.file` | Bootstrap writes `SERVERLESS_READY`, publish addresses, and node ID after `start` returns. The marker is a startup milestone. The launcher or probe needs to account for stale files across repeated container starts. |
| `GET /_serverless/health` | Process liveness based on the node's `started` flag. Startup sets the flag before bootstrap attaches the store. The endpoint includes a local observation of membership size. |
| `GET /_serverless/ready` | Returns 200 when started and `SearchReadiness` is `READY`. Returns 503 for startup, warming, and drain. With warm-on-join off, the search state starts ready. Neither the marker nor the endpoint requires a successful lease renewal. |
| Local `lease.valid_now` in `GET /_serverless/stats` | Reports local lease validity. The lease object is omitted before the metadata plane is attached. This provides a second observation for a readiness design. It measures local validity, so the acceptance test still needs to prove that another Pod can route to the published address. |
| `POST /_serverless/drain` | Puts a search-capable node in `DRAINING`, attempts lease renewal without the search role, and asks peers to copy hot blocks and open readers. It is a search handoff. A mixed-role node continues to advertise ingest during search drain. Writer publication and release happen during normal shutdown. Repeated drain requests have no further effect. |
| JVM termination signal | The shutdown hook optionally drains search, quiesces reconcile work, attempts writer publish and release, releases the lease, then closes the node and store. Hard-kill recovery goes through expiry, takeover, and WAL replay. |

Warm-on-join defaults off. When enabled, a search-capable Pod advertises its search role after warming to the configured fraction of peer blocks, or after the three-minute default timeout. A failed warm-up can also turn it ready. `serverless.search.drain.on_shutdown` defaults to the warm-on-join setting. The drain's two-minute default peer-wait allowance starts after lease renewal and peer lookup, and a settle delay follows when peers were found. Budget time for the full shutdown sequence and writer handover, including a slow store. `GET /_cluster/health` is a compatibility endpoint. Without a named index it reports the membership view and `complete: false`. An index-scoped query checks serviceability under serverless rules. Keep probe liveness independent of a shared-store outage, and verify traffic eligibility when initial lease publication fails or a lease lapses.

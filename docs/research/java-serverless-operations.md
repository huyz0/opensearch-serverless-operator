# Operating the Java serverless shell on Kubernetes

This is a source-based assessment for the operator. The branch already provides search warm-up and drain, per-node lease observations, and failure tests. The deployment work is to package the shell, wire those signals into traffic and rollout behavior, and test the full path with Kubernetes. The [architecture](java-serverless-architecture.md) and [deployment contract](java-serverless-runtime.md) describe the Java behavior behind these checks.

## Rollout and scale decisions

| Decision | Evidence and implications |
| --- | --- |
| Mixed-role or separate pools | Unset roles give each node ingest and search. Separate pools let capacity grow independently. Explicitly empty roles give a coordinator-only process. A request can enter through any role and forward inside the shell, so pool-targeted Services can isolate load but do not enforce authorization. Test loss of the last ingest node separately from loss of a search node. [Role parser](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/node/NodeAssembly.java#L173) · [Role split tests](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/NodeRoleSplitTests.java) |
| Deployment or StatefulSet | A Deployment is a candidate because the store holds durable truth. A fresh local home can change the internal node ID and discards any cache stored in that home. The published branch includes a fresh-home crash-recovery test, but the workload choice still needs a Kubernetes test with a disposable object store, fresh local paths, realistic replay size, and normal shutdown. A StatefulSet remains an option if stable storage or identity has a demonstrated value. [Bootstrap and shutdown](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/ServerlessBootstrap.java) · [Pilot readiness](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/pilot-readiness.md) |
| What gates client traffic | Separate process startup, search readiness, and valid membership. The shell's readiness route covers the first two as described in the [deployment contract](java-serverless-runtime.md). A test that fails first lease publication distinguishes a probe that checks the intended contract from a probe that only sees HTTP. Verify direct native transport between Pods. [Readiness code](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/ServerlessReadyHandler.java) · [Lease stats](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/StatsHandler.java#L607) |
| How to terminate | Signal the JVM and give it enough time to run the full shutdown path. Decide whether to use built-in shutdown drain or a controlled pre-stop drain after testing both traffic removal and latency. Search drain changes peer routing and cache placement. Writer handover still needs the shutdown hook. The full sequence can exceed the default Kubernetes grace period when search drain is enabled. [Shutdown hook](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/ServerlessBootstrap.java#L407) · [Search drain](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/warm/SearchDrain.java) |
| Which runtime values make good scaling signals | `fleet.wanted_nodes` in the stats response is a local writer estimate from advertised one-minute used and refused shard counts, targeting 80% of average reported capacity. It uses cached lease observations, tolerates some staleness, and omits the fleet estimate from the response when there are no eligible samples. It says little about reader capacity, store-wide slowdown, or abrupt loss of a large writer. Observe it alongside queue age, CPU, cache and search latency before enabling autoscaling. [Fleet estimate](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/node/FleetPlacement.java#L61) · [Stats rendering](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/StatsHandler.java) |
| How to upgrade | Pin the old and new image digests to source revisions. Test native forwarding and shared metadata/WAL/segment formats with both running. Then test graceful replacement, hard-kill recovery, and rollback using a populated bucket. The current branch has no operator-level compatibility promise for arbitrary version pairs. [Forwarding router](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/transport/ShardRouter.java) · [WAL format implementation](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/nodelog/NodeLogBlob.java) |

## Health, performance, and diagnostics

- **Readiness and membership.** Sample local `/_serverless/ready` and `lease.valid_now` with node ID. Review lease expiry, renew failures, and peer reachability separately. One node's membership list is its local view. Avoid a frequent all-node status fan-out for Pod probes. [Readiness handler](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/ServerlessReadyHandler.java) · [Stats handler](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/StatsHandler.java)
- **Failure and capacity.** Stats expose shard counts, admission and refusals, writer-open phases, backpressure and store counters. An optional all-node request reports peer failures. Correlate slow takeover with queue age, fencing, replay, and shard-open phases. Export bounded metrics and keep document, index, and tenant identifiers out of general metric labels. [Stats handler](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/StatsHandler.java) · [REST metrics](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/RestRequestMetrics.java) · [Pilot measurement guidance](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/pilot-readiness.md)
- **Telemetry.** The fork wires OpenSearch telemetry services into the shell. The telemetry feature flag and metric or trace settings must be active with a suitable plugin, otherwise the shell can use no-op services. Protocol spans have rate, in-flight, and lifetime limits. At this revision, `opensearch.serverless.trace.dropped_spans` distinguishes rate and in-flight limits. Check provider and exporter wiring in the image. [Telemetry wiring](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/NodeTelemetry.java) · [Trace admission](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/shell/TraceAdmission.java) · [Export integration](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/plugins/telemetry-otel/src/main/java/org/opensearch/telemetry/tracing/OTelResourceProvider.java)
- **Tenant usage.** `/_serverless/usage` provides node-local usage for the branch's collector. The default guardrail mode is observe. Cost grouping and limit enforcement do not grant access or establish tenant isolation. Make enforcement a deliberate deployment choice after checking collector samples through restarts and membership changes. [Usage handler](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/rest/UsageHandler.java) · [Guardrail settings](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/shell/src/main/java/org/opensearch/serverless/usage/UsageSettings.java) · [Usage collector](https://github.com/huyz0/OpenSearch/blob/e71d42331a3ec82ec01109a5bb42d6a9a9162a5c/serverless/tools/usage_collector.py)

## Evidence in the branch

| Evidence | What it covers | What it leaves to the operator |
| --- | --- | --- |
| Testkit and request budgets | Role split, warm-up and drain, REST semantics, fencing, durability, and request-count budgets. Budgeted round trips use a metered filesystem fixture and synthetic delay. | Pod readiness, networking, and behavior under container limits. Treat budget rows as regression gates for their fixtures. |
| `processTest`, `s3Test`, `tlsTest`, `pluginTest` | Forked JVMs, real local object-store interactions when provisioned, in-process TLS integration, and assembled plugins. | Production image layout, certificate distribution, credential refresh, Service routing, and Pod termination. |
| RustFS smoke and fleet gate | Smoke includes loss of required log data, ambiguous store writes, and crash recovery. Fleet tests distinguish writes to affected shards from healthy traffic during a bounded kill window. The workflow uses a local RustFS fixture. | Repeat equivalent checks with a Kubernetes Service and its rollout, kill, and replacement behavior. |
| Pilot measurements | The source notes describe one three-node RustFS shakedown with an eight-second lease, 48 indices, and 20 offered writes per second. It recorded zero losses among 1,969 acknowledged writes, along with 416 unknown outcomes for the affected cohort in its observation window. | Those conditions do not establish a recovery SLO or throughput limit for a Kubernetes deployment with the default 30-second lease. |

## Kubernetes checks that resolve the open questions

1. **Image and initial join.** Start a non-root JVM in each of two Pods on one disposable RustFS bucket. Check that each advertises its own reachable transport address, that both join, and that ingest and search requests cross Pods. Repeat with object-store failure during initial lease publication and after successful startup. Confirm the intended traffic behavior while the processes remain alive.
2. **Graceful replacement.** Write with explicit IDs and record acknowledged responses, realtime reads, and query freshness. Delete one serving Pod while traffic continues. Observe endpoint removal, search-role withdrawal if draining, writer handover, replacement readiness, and reads of acknowledged IDs. Measure time across pre-stop, JVM shutdown, and peer rerouting.
3. **Hard loss and cold recovery.** Kill a writer without its shutdown hook and attribute writes by the shards that writer owned. Require healthy traffic and affected-shard recovery separately. Preserve unknown outcomes in the ledger. Then replace all Pods with fresh local state on the same bucket and verify acknowledged documents. Repeat with a slow store and enough load to exercise replay disk and memory.
4. **Changes and retention.** Test a configuration or image rollout on populated data, check that replicas keep serving and the underlying store stays bound, then delete and recreate the resource using the same external bucket. Exercise credential and certificate rotation through the chosen image and launcher. Check the rejection of a store binding change if the first API makes it immutable.

No Kubernetes scenario or Java test was run for this study. The code and existing suites identify the behavior to validate.
